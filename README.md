# pnpm-windows-panic

Minimal reproduction for pnpm 12 failing on Windows when the project lives on a
mapped network drive (for example, `H:` mapped to `\\server\share\user`).
pnpm 11 installs and runs scripts from the same location without errors.

The same project installs and runs normally from a local disk.

## Contents

- `package.json`:
  - pins `pnpm@12.16.1` through `packageManager`;
  - pins Node.js 24.20.0 through `devEngines.runtime`;
  - declares one small dependency (`is-number`);
  - has a `test` script that prints the script's working directory.
- `pnpm-lock.yaml`: the lockfile generated by pnpm 12.16.1.
- `scripts/bootstrap.ps1`: the bootstrap script from the project where the
  failure was first observed. It checks that pnpm is installed through WinGet
  and that `NODE_USE_SYSTEM_CA=1` is set, runs
  `pnpm install --frozen-lockfile`, and then checks the pnpm and Node.js
  versions the project selects.

## Environment

- Windows 11
- pnpm 12.16.1, installed with `winget install --exact --id pnpm.pnpm`
- Home directory on `C:`; repository on a mapped network drive

## Steps to reproduce

1. Map a network share to a drive letter, for example `H:` →
   `\\server\share\user`.
2. Clone this repository onto the mapped drive:

   ```powershell
   git clone https://github.com/dylan-bakr/pnpm-windows-panic H:\repos\pnpm-windows-panic
   cd H:\repos\pnpm-windows-panic
   ```

3. Install the project:

   ```powershell
   .\scripts\bootstrap.ps1
   ```

   Running `pnpm install --frozen-lockfile` directly installs the same way.

4. Run a script:

   ```powershell
   pnpm test
   ```

## Expected

As with pnpm 11, the install succeeds and `pnpm test` prints
`H:\repos\pnpm-windows-panic`.

## Actual

The install chooses `H:\.pnpm-store` as the store, then fails to import
packages into the `\\?\UNC\…` form of the project path:

```text
× installing dependencies
╰─▶ failed to import "H:\.pnpm-store\v11\files\…-exec" to
    "\\?\UNC\server\share\user\repos\pnpm-windows-panic\node_modules\.pnpm\…":
    The system cannot find the file specified. (os error 2)
```

`pnpm test` reinstalls dependencies before running the script
(`verifyDepsBeforeRun`), and that install panics:

```text
× Main thread panicked.
├─▶ at pnpm\crates\config\src\defaults.rs:50:39
╰─▶ current dir is an absolute path with drive letter
```

The script then starts `cmd.exe` with the UNC path as its working directory.
`cmd.exe` does not support UNC working directories and falls back to
`C:\Windows`:

```text
CMD.EXE was started with the above path as the current directory.
UNC paths are not supported.  Defaulting to Windows directory.
```

## Notes

- [`default_store_dir_windows`](https://github.com/pnpm/pnpm/blob/v12.16.1/pnpm/crates/config/src/defaults.rs)
  calls `get_drive_letter(current_dir).expect(…)`. That call panics when the
  current directory has a UNC prefix (`Prefix::UNC` or `Prefix::VerbatimUNC`)
  instead of a drive letter.
- On Windows, `std::fs::canonicalize` turns a mapped-drive path into a
  `\\?\UNC\…` path. pnpm appears to use that canonical form of the project
  directory for imports, for the store-default lookup, and as the working
  directory for scripts.
